01

Scope and plain-language summary

Tideglass is a self-contained aquarium simulation and narrative game that runs inside its extension popup. It does not inspect the websites you visit. The aquarium, fish behavior, chemistry readings, depth anomalies, acoustic returns, and care log are generated by code bundled with the extension.

The practical privacy summary is simple: gameplay remains on the device. Tideglass uses the extension page’s localStorage to remember the simulated tank between popup sessions, and it does not send that state to a developer server, analytics provider, advertising network, or cloud account.

The unusual measurements in Tideglass are fictional game mechanics. A depth probe, pressure value, sonar return, or reflection count shown by the game is not a sensor reading from the player’s physical environment.

02

Chrome permissions

The production manifest declares an empty permissions array. Tideglass does not request tabs, history, activeTab, scripting, storage, notifications, geolocation, camera, microphone, downloads, bookmarks, clipboard, or host access.

The game does not need a Chrome storage permission because localStorage belongs to the extension page itself. The absence of host permissions also means Tideglass has no declared ability to read or alter arbitrary webpages.

  • No host permissions are declared.
  • No content scripts are packaged.
  • No background service worker is needed for gameplay.
  • No optional permissions are requested later.
03

Information created during play

Tideglass creates game-state information as the player cares for the aquarium. This includes simulation time, light and filter state, temperature, oxygen, pH, water level, food availability, algae level, calculated volume, pressure factor, progression stage, probe and sonar unlock state, and recent care-log entries.

Each simulated resident also has local gameplay values such as species label, position, movement vector, hunger, stress, simulated depth, and anomaly state. These values describe fictional aquarium entities. They do not represent real animals, real telemetry, or information collected from outside the game.

04

What the player provides

The player provides only ordinary game interactions such as pressing Feed, Water change, Light, Filter, Lower, Ping, Inspect glass reflection, or New tank. Tideglass does not provide a text field for personal information and does not ask the player to identify themselves.

Button choices are used immediately to update the local simulation. They are not converted into advertising categories, behavioral profiles, or remote analytics events.

05

Local storage and save format

The game stores one JSON save record under the localStorage key tideglass-v1. That record contains the current local simulation and a timestamp used to estimate limited offline progression when the popup is opened again.

The save record can contain recent care-log text generated by the game, but those messages are selected by the bundled simulation code. The extension does not copy text from webpages, documents, the clipboard, messages, or other applications into the save.

The offline catch-up calculation is deliberately capped. The timestamp is used only to advance the fictional tank by a limited amount; it is not sent away or used to build an activity history.

06

Retention and deletion

The local save remains in the browser profile until the player resets the tank, clears the extension’s local data, removes the extension, or the browser otherwise deletes that storage. Tideglass does not maintain a second copy on a remote server.

Using New tank replaces the current gameplay state with a fresh tank after confirmation. Browser-level removal or site-data controls can also remove the saved value. Because there is no account and no server copy, there is no separate cloud-deletion request to submit.

07

Aquarium rendering

The aquarium view is drawn locally with the browser canvas API. Fish silhouettes, plants, gravel, bubbles, water gradients, and movement are generated from the local state. The renderer does not request photographs, camera access, image libraries, or network textures.

Animation uses requestAnimationFrame while the popup is open. It does not create a background tracker after the popup closes. The simulation’s slower state progression is saved locally so that reopening the popup can resume the tank.

08

Depth, sonar, and reflection mechanics

Depth-probe readings, acoustic returns, measured-volume discrepancies, pressure values, and reflected-resident counts are fictional outputs derived from the game’s progression stage and pseudo-random simulation state. They are designed to create the cosmic-horror premise that the interior of the aquarium no longer agrees with its visible dimensions.

The word “sonar” in the interface refers only to a visual game instrument. Tideglass does not access a microphone, speaker input, ultrasonic sensor, network device, Bluetooth device, or physical aquarium equipment. “Inspect glass reflection” similarly does not access a camera.

09

Network behavior

Tideglass contains no feature that needs to contact an application server. The packaged game does not use fetch, XMLHttpRequest, WebSocket, remote modules, or a cloud save API for gameplay.

Because the game does not transmit its save, we do not receive the player’s aquarium progress, anomaly stage, care choices, play duration, IP address, or browser activity from Tideglass itself.

The browser may still contact its own vendor infrastructure for extension installation or update checks. That browser behavior is separate from Tideglass’s game code.

10

Analytics and advertising

Tideglass does not contain product analytics, event analytics, attribution tracking, ad measurement, fingerprinting, sponsored content, personalized advertising, or an advertising identifier. There is no telemetry event for feeding a fish, seeing an anomaly, opening the popup, or resetting the tank.

The game also does not sell or rent data. With no game-state transmission, there is no remote gameplay dataset to sell.

11

Webpage and browsing access

Tideglass runs in its own extension popup. It does not inject a script, stylesheet, overlay, or frame into the current tab. It does not read page titles, page text, links, forms, cookies, history, bookmarks, search queries, or tab URLs.

Opening Tideglass while a sensitive webpage is visible does not grant the game access to that webpage because the extension does not request the permissions that would be required for such access.

12

User controls and failure paths

The player can turn the light and filter on or off, perform a water change, feed the tank, operate unlocked fictional instruments, and start a new tank. The interface displays the local readings that the simulation is currently using so that state changes are visible rather than hidden.

If stored JSON is missing or does not pass the game’s basic save validation, Tideglass starts a fresh local state instead of attempting to upload, repair, or infer data from another source. The game caps offline advancement to avoid runaway state changes after a long absence.

13

Children and age considerations

The extension is a general-audience local game. It is not designed to request a child’s name, email address, location, school, contacts, photographs, or other identifying information. The game does not provide chat, social posting, public profiles, matchmaking, purchases, advertising, or account creation.

Because no information is transmitted to us, the extension does not build a remote profile of a child or adult player. A parent or guardian who wants to remove the game’s local progress can use the reset control or remove the extension and its local site data through the browser.

14

Security model

The extension has a deliberately small attack surface: it requests no Chrome permissions, does not inject into websites, does not load executable code from the Internet, and does not accept network-delivered game state. Its HTML, CSS, JavaScript, icons, and game rules are packaged with the extension.

Local browser storage is not a secure vault for secrets. The game therefore does not ask the player to enter passwords, financial details, private notes, authentication tokens, or other sensitive material. Progress data should be treated as ordinary local game state.

No security system can guarantee absolute protection against compromise of the device or browser itself. The policy describes the extension’s own behavior, not the security of the operating system around it.

15

Third parties and service providers

The extension does not include advertising SDKs, analytics libraries, crash-reporting clients, social SDKs, payment processors, cloud databases, external fonts, remote game engines, or third-party tracking pixels. No third party is given game telemetry by the extension because the extension does not transmit game telemetry.

Chrome and the operating system may independently provide platform-level services such as extension installation, update delivery, browser storage, process isolation, or crash handling. Those are browser/platform functions rather than data integrations implemented by this extension.

16

Policy changes

If a future version changes what information the extension handles, adds a permission, introduces an online service, or materially changes retention behavior, this policy should be updated before or with that release. The effective date and version record at the top are intended to make that change visible.

A cosmetic rewrite of the game interface does not itself change privacy behavior. A change from local-only processing to network processing would be material and would require a corresponding disclosure.

17

Contact and questions

Questions about this privacy policy or the extension’s behavior can be sent through the support contact associated with the extension’s official Chrome Web Store listing. Using the listing contact avoids embedding an unrelated personal address in the game package and gives users a channel associated with the published product.

When asking a privacy question, players do not need to send save data, screenshots, browsing history, or device identifiers. A description of the concern and the extension version is normally sufficient.

This policy describes the packaged extension behavior for version 1.0.0. Support and privacy questions: use the support contact provided on the extension’s official Chrome Web Store listing.
